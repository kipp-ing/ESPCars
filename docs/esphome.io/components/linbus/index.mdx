The `linbus` component supports ESP32 with ESP-IDF only. Tested targets are classic ESP32, ESP32-C3 and ESP32-C6.
There is no independent ESP32-C5 exclusion; CAN Gateway rejects C5 if also configured.
Each segment needs a distinct UART and distinct GPIO pins. This component manages its own UART rather than using
[UART Bus](/components/uart/). Configuration rejects ports used by an active hardware logger or allocated
to a stock UART component. An already installed driver also fails LIN setup before UART reconfiguration.

## Passive Observation

Always set `mode: listener` for commissioning. The schema's `commander` default is a bus-driving role.

```yaml
linbus:
  id: lin_monitor
  tx_pin: GPIOXX
  rx_pin: GPIOXX
  mode: listener
```

## Configuration variables

- **id** (*Optional*, [ID](/guides/configuration-types/#id)): Instance identifier; specify it explicitly with multiple
  segments.
- **tx_pin** (**Required**, [Pin](/guides/configuration-types/#pin)): Internal ESP32 transceiver transmit pin;
  inversion is unsupported.
- **rx_pin** (**Required**, [Pin](/guides/configuration-types/#pin)): Internal ESP32 transceiver receive pin;
  inversion is unsupported.
- **cs_pin** (*Optional*, [Pin](/guides/configuration-types/#pin)): Transceiver enable pin, driven logically high
  once during
  setup; inversion and GPIO expanders are supported.
- **baud_rate** (*Optional*, int): Bus speed, 1000–20000 bits/s. Defaults to `19200`.
- **uart_port** (*Optional*, enum): Select a UART physically present on the target.
  - `UART_NUM_0`
  - `UART_NUM_1` *(default)*
  - `UART_NUM_2` (only on targets with a third HP UART; rejected on C3/C6)
- **mode** (*Optional*, enum): Operating role. Select `listener` explicitly to start observing.
  - `listener`: Never transmits.
  - `responder`: Answers registered identifiers.
  - `commander`: Drives scheduled headers. *(default)*
  - `master`: Deprecated alias for `commander`; warns for one release cycle.
  - `slave`: Deprecated alias for `responder`; warns for one release cycle.
- **rx_ids** (*Optional*, list): Receive framing hints, at most 32 unique identifiers. Each needs length or checksum.
  - **lin_id** (**Required**, int): Identifier, 0–63.
  - **length** (*Optional*, int): Expected payload length, 1–8 bytes.
  - **checksum** (*Optional*, enum): Expected checksum; omission allows inference/fallback.
    - `classic`
    - `enhanced`
- **on_frame** (*Optional*, automation): Runs when a selected checksum-valid frame updates.
- **on_error** (*Optional*, automation): Runs on a transport fault; `x` is a string naming the fault.
- **schedule** (*Optional*, list): Commander-only header schedule, at most 16 unique identifiers. Transmits from boot.
  - **lin_id** (**Required**, int): Identifier, 0–63.
  - **interval** (**Required**, [Time](/guides/configuration-types/#time)): Header interval, at least `1ms`.
  - **length** (*Optional*, int): Receive length hint, 1–8 bytes; otherwise inferred.
- **responses** (*Optional*, list): Published responses, at most 16 unique identifiers; forbidden in listener mode.
  - **lin_id** (**Required**, int): Identifier, 0–63.
  - **data** (**Required**, byte list): Zero to eight payload bytes.
  - **checksum** (*Optional*, enum): Response checksum. Diagnostic identifiers always use classic.
    - `enhanced` *(default)*
    - `classic`
- **self_test** (*Optional*, boolean): Commander-only physical loopback exerciser; transmits. Defaults to `false`.
- All other options from [Component](/components/esphome/).

## Automations

### `on_frame` Trigger

Receives `data` (byte vector) and `data_length`. Read within the supplied length. All handlers for an ID
receive the same latest frame update; frames arriving between main-loop deliveries are coalesced once per ID.

```yaml
linbus:
  tx_pin: GPIOXX
  rx_pin: GPIOXX
  mode: listener
  on_frame:
    - lin_id: 0x22
      then:
        - logger.log: "LIN frame observed"
```

**Configuration variables:**

- **lin_id** (**Required**, int): Selected identifier, 0–63.
- **length** (*Optional*, int): Receive length hint, 1–8 bytes.
- **checksum** (*Optional*, enum): Expected checksum; omission allows inference/fallback.
  - `classic`
  - `enhanced`
- **trigger_id** (*Optional*, [ID](/guides/configuration-types/#id)): Generated trigger identifier; normally omit it.
- **then** (**Required**, automation): Actions to run on a frame update.

### `on_error` Trigger

Runs on a fault; the string `x` identifies its class.

```yaml
linbus:
  tx_pin: GPIOXX
  rx_pin: GPIOXX
  mode: listener
  on_error:
    then:
      - logger.log: "LIN transport fault"
```

**Configuration variables:**

- **trigger_id** (*Optional*, [ID](/guides/configuration-types/#id)): Generated trigger identifier; normally omit it.
- **then** (**Required**, automation): Fault handling actions.

### `linbus.update_response` Action

Warning: publishing response bytes enables transmission on a responder or commander bus.
An existing entry keeps its checksum mode; a new entry uses enhanced checksum. A listener remains passive.
Changing payload size updates the derived receive length for subsequent headers. An explicit length in
`rx_ids`, `on_frame`, or `schedule` must agree; an incompatible update is refused with a warning and
keeps the old response. Empty data clears the response and its derived length; explicit hints remain.

```yaml
then:
  - linbus.update_response:
      id: lin_monitor
      lin_id: 0x22
      data: [0x01]
```

**Configuration variables:**

- **id** (*Optional*, [ID](/guides/configuration-types/#id)): LIN instance; inferred if unambiguous.
- **lin_id** (**Required**, templatable int): Response identifier, 0–63.
- **data** (**Required**, templatable byte list): Zero to eight response bytes.

### `linbus.run_self_test` Action

Warning: enabling this exerciser transmits on the LIN bus; it requires commander mode and a live transceiver.

```yaml
then:
  - linbus.run_self_test:
      id: lin_monitor
      enable: false
```

**Configuration variables:**

- **id** (*Optional*, [ID](/guides/configuration-types/#id)): LIN instance.
- **enable** (*Optional*, templatable boolean): Start or stop self-test. Defaults to `true`.

BASIC PASS latches while test traffic continues until explicitly stopped. Only `enable: false`
clears that latch and restores the exact pre-test schedule and response tables, including overwritten
user entries. Restored user traffic resumes; in-flight UART bytes may finish. Edits to those tables
during a run are temporary. All nine cases must fit in both tables, or installation is refused
atomically with an `INCOMPLETE` log and component warning; the pass sensor stays false.

## Transmitting Roles

Warning: commander schedules and responder publications transmit on the LIN bus.
The following is a fictional schedule for an isolated test segment, after observing that segment.

```yaml
linbus:
  tx_pin: GPIOXX
  rx_pin: GPIOXX
  mode: commander
  schedule:
    - lin_id: 0x22
      interval: 100ms
```
